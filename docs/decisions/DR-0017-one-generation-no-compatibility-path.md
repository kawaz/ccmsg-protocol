# DR-0017: `PROTOCOL_VERSION` は世代を表し、互換経路を持たない

- Status: Active
- Date: 2026-09-14

## Context

契約は 1 つの形を述べる物で、その形は変わる。変わった時に、古い形を名乗る相手をどう扱うかを決める必要がある。

## Decision

- `PROTOCOL_VERSION` は世代を名指す整数 1 つ
- **1 つの世代の中で足してよいのは、任意フィールドと丸ごと新しい op だけ**。削除と意味の変更は世代を上げる
- 別の世代を名乗る相手は拒む。client の接続でも mesh の link でも同じ。互換のための変換経路は持たない

## Alternatives Considered

- 案 A: 版を細かく刻み、機能ごとに交渉する
  - 不採用理由: 実装は組み合わせの数だけ分岐を持つことになる。契約が 1 つの形を述べる物でなくなり、何が通るかは実行するまで分からない
- 案 B: 旧世代を受け入れて変換層を置く
  - 不採用理由: 変換は「この 2 つは同じ意味だ」という主張で、それは契約が述べていない事柄。世代を上げるのは意味が変わった時なので、変換層は契約が否定した同一性を実装が主張することになる

## Consequences

- 削除や意味の変更を含む変更では、daemon・web UI・CLI・plugin が同時に追従する
- 世代違いの相手は接続の時点で落ちるので、食い違いは実行中ではなく接続時に現れる
