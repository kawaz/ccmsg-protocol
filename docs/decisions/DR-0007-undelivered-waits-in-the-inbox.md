# DR-0007: 渡らなかったメッセージは inbox で待ち、人が読んでも消費されない

- Status: Active — ✅ 実装済
- Date: 2026-09-14

## Context

宛先のセッションが今すぐ受け取れないことは珍しくない (起動中、停止中、消えた、mesh の向こうに届かない、inbox が満杯、今は受け取らない)。これを失敗として返すと、送り手は待つ / 別のセッションに言う / 送り直す の判断材料を持たない。一方で、待っているメッセージを人が見られなければ「送ったのに何も起きない」が観測できない。

## Decision

- **すぐ渡らなかったことは失敗ではない**。応答は inbox に入ったことと **理由**を述べ、送り手は待つか別の宛先にするかを選べる
- `inbox` topic は 1 つの購読で 2 つの意味を持つ。**セッションが購読すれば、届いた物は渡されたことになり inbox から出る。人が購読しても inbox は動かない** — 人は誰宛でもないから。この非対称が閲覧を成立させる (見ただけで消費する閲覧は、開くことで誰にも届かなくする)
- 消費するかどうかは frame に述べる。`granularity` の隣の属性にはしない — 折り方の話でも誰が購読できるかの話でもなく、届いた物に対して購読者がすることは同じだから
- 人は 1 つの購読で全セッションの inbox を持つので、その行は宛先 `to` を持つ。セッション自身の購読では行が宛先を繰り返す必要は無い
- inbox からの退場は `removed: true` の要素として、`mid` と **理由** (`delivered` / `expired` / `dropped`) を伴って届く。理由は watcher が導出できない唯一の物で、描き分けの対象でもある: `delivered` は受け手が持っていてその後の話が transcript に続く、他の 2 つは届かなかったし今後も届かない

## Alternatives Considered

- 案 A: 人の閲覧も消費する (購読は 1 つの意味だけ持つ)
  - 不採用理由: 閲覧した時点で誰にも渡らなくなる。待っている物を見る手段が無くなる
- 案 B: 退場を「一覧から消えていること」で表す
  - 不採用理由: 変化の一覧における不在は何も述べない ([DR-0005](DR-0005-observation-is-snapshot-plus-delta.md))
- 案 C: 退場に理由を持たせない
  - 不採用理由: 渡ったのか、消えたのかが読めない。人は同じメッセージを 2 度見る (待っている所と、受け手の transcript) ので、両者を繋ぐ `mid` と、繋がらない理由の両方が要る
- 案 D: 渡らなかったことをエラーとして返す
  - 不採用理由: 何も失敗していない。送り手が読むべきなのは失敗ではなく「今どこにあるか」

## Consequences

- 送り手は応答の理由を読んで判断でき、再送は選択であって義務ではない
- inbox は永続で、保持の期限と件数は契約が持つ ([DR-0012](DR-0012-retention-windows-in-the-contract.md))
