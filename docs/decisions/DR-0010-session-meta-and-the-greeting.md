# DR-0010: セッションの素性は 1 箇所で述べ、挨拶はフィールド単位に取る

- Status: Active
- Date: 2026-09-14

## Context

セッションがどこで何として動いているか (`repo` / `ws` / `cwd` / `repo_root` / `branch` / `transcript_path` / `title` / `model` / `effort`) は、セッションが挨拶で述べ、instance が行に載せて返す。述べる側と返す側が別々に名前と型を持てば、同じ物が 2 通りに綴られる。さらに 1 つのセッションは短命なプロセスの連なりとして instance に届き、どのプロセスも全フィールドを知っているとは限らない。

## Decision

- 素性の名前と型は `src/session-meta.ts` の 1 箇所に置き、`hello.session` と `peers` の行が同じ物を使う
- 述べられなかった物は省く。instance が導出できる物は instance が導出する
- **挨拶はフィールド単位に取る**。あるフィールドを含まない挨拶は、そのフィールドを撤回しない
- `protocol_version` は、その行自身の接続が名乗った世代。接続を持たない行 (instance の状態ファイルがセッションを生きていると述べているだけの行) には無い
- `stopped_at` への入口は `session.stopping` ただ 1 つ。セッション自身が「これから止まる」と述べ、instance は切断が来るまでその宣言を保持して、2 つを **この順の 1 つの出来事**として扱う。呼べる role は `session` だけで、harness の終了 hook か `ccmsg` CLI が代行する。宣言せずに消えたものは、宣言が無いことで分かる — 意図した停止と喪失を分けるのは宣言であって観測ではない
- 忙しさは行の属性として `gateway_active_at` (最後に推論が走った時刻) が持つ。**フラグではなく時刻**なのは、要求が飛んでいなくなる瞬間を誰も観測しないから (client が自分の閾値で新しさを読む)。gateway を持たない instance では不在で、それは「静かだ」ではなく「推論を観測している物が無い」を意味する
- 人が付けた印 (`pinned`) は観測された素性ではないので、分類に畳まず行の隣に並べる

## Alternatives Considered

- 案 A: 挨拶を丸ごとの置き換えとして扱う (不在は撤回)
  - 不採用理由: 1 セッションは短命プロセスの連なりで、どのプロセスも全フィールドを知らない。不在を撤回と読むと、後続のプロセスが前の申告を消す
- 案 B: 素性を挨拶側と行側で別々に定義する
  - 不採用理由: 同じ物が 2 通りに綴られ、片方だけ増えても誰も気付かない
- 案 C: 停止を観測だけで決める (切断したら停止)
  - 不採用理由: 意図して止めたのか失われたのかが分けられない
- 案 D: 忙しさを boolean にする / 分類に畳む
  - 不採用理由: 要求が終わる瞬間は観測できないので boolean は誰も落とせない。接続中はどの状態でも忙しくなり得るので分類に畳むと片方が消える

## Consequences

- 素性を 1 つ足す変更は `src/session-meta.ts` の 1 箇所で済む
- 挨拶がフィールド単位なので、値を消すには消したことを述べる手段が別に要る
