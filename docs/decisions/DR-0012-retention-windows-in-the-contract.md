# DR-0012: 未配送メッセージと失われた行の保持期限を契約が持つ

- Status: Active
- Date: 2026-09-14

## Context

渡らなかったメッセージも、失われたセッションの行も、いつまでか保持される。期限を instance ごとの設定に置くと、送り手は自分のメッセージがいつまで待つのかを読めず、人は戻ってきた時に何が残っているのかを予測できない。

## Decision

- `INBOX_RETENTION_MS` と `LAST_LIVE_RETENTION_MS` をどちらも 7 日、`INBOX_MAX_PER_SID` を 256 として契約が持つ
- 2 つの期限を分けない。人が戻ってくる先は 1 つの物 — **セッションと、そこへ言われた物** — なので、片方だけが先に消えれば、残った方が何の話か言えなくなる
- 件数は、受け手が 1 セッション分として渡される量に合わせる。契約が受け付ける量を、受け手がまだ渡され得る量に留める

## Alternatives Considered

- 案 A: 期限を instance の設定にする
  - 不採用理由: 送り手は自分のメッセージがいつまで待つのかを読めない。契約が述べるからこそ、送り手は待つか別の宛先にするかを判断できる
- 案 B: inbox と行の期限を別々にする
  - 不採用理由: 片方だけ残る状態ができる。メッセージだけが残ればどのセッション宛だったかが語れず、行だけが残れば何が届かなかったかが語れない
- 案 C: 件数の上限を置かない
  - 不採用理由: 受け手が渡され得る量を超えて溜め込むことになり、古い物のために新しい物を断ることになる

## Consequences

- 満杯の inbox に新しいメッセージが来た時、古い物が `dropped` として退場する ([DR-0007](DR-0007-undelivered-waits-in-the-inbox.md))
- 期限の変更は契約の変更で、両実装が同時に追従する
